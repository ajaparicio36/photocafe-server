# Issue tracker: Local Markdown

Issues and specs for this repository live in `docs/improvements/tracker/`.

## Conventions

- One feature per directory: `docs/improvements/tracker/<feature-slug>/`.
- The spec is `<feature-slug>/spec.md`.
- Implementation issues are individual files at `<feature-slug>/issues/<NN>-<slug>.md`, numbered from `01`.
- Record triage state in a `Status:` line near the top of each issue. Use the roles in `triage-labels.md`.
- Append conversation under `## Comments`. AI triage comments begin with `> *This was generated by AI during triage.*`.
- Link related issues and evidence in other repositories. Keep each issue in the repository that owns its change.

When a skill says to publish to the issue tracker, create or update the relevant local file here. When it says to fetch a ticket, read the supplied local file. Ask for a file path if an issue number is ambiguous across feature directories.

## Wayfinding

For an effort, use `<feature-slug>/map.md` for Notes, Decisions-so-far, and Fog, and one numbered child ticket per question in `issues/`.

A child ticket has a `Type:` of `research`, `prototype`, `grilling`, or `task`. Wayfinding lifecycle uses `State: open`, `State: claimed`, or `State: resolved`. Reserve `Status:` exclusively for the default triage roles.

Use `Blocked by: NN, NN` for dependencies within the effort. The frontier is open, unblocked, and unclaimed tickets, lowest number first. Set `State: claimed` before working; on completion append `## Answer`, set `State: resolved`, and link the answer from the map's Decisions-so-far.
